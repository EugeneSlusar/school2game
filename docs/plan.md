# school2game (бывший «Табличный спорт»): план и решения

Всё, о чём договорились в диалоге при создании игры.

## Идея

Соревновательная игра для телефона для детей 5 класса. Игроки решают примеры на умножение на скорость, каждый верный ответ приносит очки. Вид спорта (футбол, баскетбол и другие) это оформление и анимация, математика в них одинаковая.

## Согласованные решения

| Вопрос | Решение |
|---|---|
| Виды спорта | футбол, баскетбол, бейсбол, гольф, хоккей, гонки; два игрока могут выбрать разные виды |
| Составы | 1×1, 2×2, 3×3 (командные виды) |
| Длина матча | 2 минуты или до набора очков (см. систему очков) |
| Режимы | сначала против ботов, потом онлайн |
| Предмет | сейчас только умножение; позже деление и другие предметы |
| Уровни | лёгкий, средний, сложный |
| Режим учителя | не нужен |
| Хостинг | позже автодеплой на свой сервер или публикация в Google Play |
| Победитель | у кого больше очков; вид спорта влияет только на картинку |

## Три уровня

| Уровень | Примеры | Время на пример |
|---|---|---|
| Лёгкий | таблица 2–5 (2×3 … 5×9) | 10 с |
| Средний | до 10×10 | 7 с |
| Сложный | до 12×12, примеры с пропуском (3 × ? = 24) и в два действия (7 × 8 + 6) | 5 с |

На примеры с пропуском даётся +1 с, на примеры в два действия +3 с.

## Система очков (выбрана при разработке V1)

- Верный ответ: +1 очко.
- Быстрый ответ (в первую половину времени на пример): ещё +1.
- Каждый третий верный подряд: гол или бросок, +3.
- Ошибка или конец времени обрывает серию. После ошибки ввод блокируется на 1 секунду.
- Матч идёт 2 минуты или до 50 очков на игрока (в 2×2 цель команды 100).
- Значения лежат в константах в начале скрипта `www/index.html` (`MATCH_SECONDS`, `POINTS_PER_PLAYER`, `SHOT_BONUS`, `FAST_SHARE`, `LOCK_SECONDS`).

## Механика

- Оба игрока получают одинаковую последовательность примеров, каждый отвечает в своём темпе.
- Ответ вводится на экранной клавиатуре, проверка срабатывает сама, когда набрано столько цифр, сколько в ответе.
- В командных играх у каждого игрока свой пример, очки команды складываются.
- Боты отвечают с разной скоростью и точностью в зависимости от уровня.

## Этапы

1. **V1 (сделано):** игра против ботов, 3 уровня, футбол и баскетбол, форматы 1×1 и 2×2, экран результата с ошибками для повторения, рекорды на устройстве. Один HTML-файл, работает в браузере телефона.
2. **V2:** бейсбол, гольф, хоккей, гонки, формат 3×3, звёзды и формы, звуки, разбор ошибок.
3. **V3:** онлайн-дуэли и команды по коду комнаты (сервер на Node.js, WebSocket). Примеры генерируются по общему seed (`mulberry32`), это уже заложено в `makeQuestion`.
4. **V4:** автодеплой на свой сервер, публикация в Google Play (подписанный релизный AAB).

## Что реализовано в V1

- Меню: вид спорта, состав, уровень, правила, рекорды.
- Матч: обратный отсчёт, табло, поле как схема тактики, мяч по маршруту атаки, гол или бросок с конфетти, полоса времени с подсказкой +2/+1, клавиатура, пауза.
- Результат: победа, поражение или ничья, точность, лучшая серия, самый быстрый ответ, список ошибок.
- Светлая тема в виде тетради в клетку, тёмная в виде школьной доски.
- Шрифты Russo One и Neucha лежат в `www/fonts`, игра работает без интернета.

## Что реализовано в V1.1 (предметы и диагностика)

- Предметы и темы: математика (умножение, деление), русский язык (словарные слова, ударения, -тся/-ться). Вопросы двух видов: ввод числа и выбор из вариантов.
- Статистика по темам на устройстве: последние 30 ответов, точность, среднее время. Тема считается слабой при точности ниже 70%, «подтянуть» до 88%.
- Меню подсказывает, что хромает. Режим «Слабые места» чаще даёт слабые темы и на 35% повторяет прошлые ошибки.
- Экран «Мой прогресс», разбивка по темам на экране результата, кнопка «Подтянуть слабое».
- В русском языке после ошибки показывается верный ответ и идёт следующий вопрос.

## Веб-версия: рейтинг и вход через Яндекс ID (в плане)

Пока развиваем только веб-версию (папка `www`, на своём сервере). Android-сборка на паузе.

**Вход. Google нельзя.** С 7 июля 2026 действует закон № 199-ФЗ (ст. 13.55 КоАП): российский сайт не может авторизовать пользователей через иностранные сервисы (Google, Apple ID). Штрафы: должностные лица 30–50 тыс. руб., юрлица 500–700 тыс., при повторе до 1,4 млн. Допустимые способы: российский номер телефона, Госуслуги (ЕСИА), ЕБС, российские сервисы (Яндекс ID, VK ID, Сбер ID). Вход по e-mail как логину, включая Gmail, сам по себе не запрещён, но вход через кнопку Google запрещён. Вход через Telegram считается зоной риска.

Решение по входу (выбрать): основной вариант Яндекс ID (по аккаунту, с которым пользователь уже вошёл в браузере, работает через OAuth), запасные VK ID и вход по номеру телефона с кодом (SMS-код платный). Режим гостя без рейтинга остаётся.

**Режим гостя и перенос данных (сделано в игре, шаг 1).**
- Данные пишутся в localStorage и зеркалом в IndexedDB; при запуске берётся более свежая копия (`savedAt`). После матча запрашивается постоянное хранилище (`navigator.storage.persist`), чтобы браузер не чистил данные сам.
- Каждый гость получает `guestId`. Каждый матч сохраняется отдельной записью с уникальным `id` (результат, предмет, тема, уровень, ответы по темам, флаг `sent`), последние 500.
- Резервная копия: в «Мой прогресс» есть код `S2G1:…`, его можно вставить на другом устройстве или после очистки браузера. Загрузка именно сливает данные (матчи по `id`, статистика темы с большим числом ответов, ошибки, рекорды), ничего не затирает.
- При входе (шаг 2): клиент отправляет на сервер `guestId` и все матчи с `sent=false`; сервер привязывает `guestId` к аккаунту и добавляет матчи идемпотентно по `id` (повторная отправка ничего не дублирует), статистику тем объединяет так же, как `mergeData`. После успеха клиент ставит `sent=true`. Если аккаунт уже имел данные, они объединяются, а не заменяются.
- Результаты гостя не попадают в общий рейтинг, пока он не вошёл; после входа гостевые матчи засчитываются задним числом.

**Рейтинг.**
- Результат матча (очки, предмет, тема, уровень, победа) отправляется на сервер и сохраняется за пользователем.
- Таблицы: общая, по предметам, за неделю. Позже: по классам и кланам.
- В таблице показывается ник и аватар-эмодзи, а не имя и фото аккаунта. Ник ребёнок выбирает сам при первом входе.
- Статистика по темам («что хромает») переезжает с устройства на сервер, чтобы работала на любом телефоне и компьютере.

**Что нужно сделать.**
1. Зарегистрировать приложение в Яндекс ID (oauth.yandex.ru) и указать адрес сайта (Callback URI), нужен домен с HTTPS. Для VK ID аналогично в кабинете VK ID.
2. Сервер на Node.js + SQLite: обмен кода OAuth на сервере и получение профиля Яндекс ID, таблицы `users`, `results`, `topic_stats`, API `POST /api/result`, `GET /api/leaderboard`.
3. В игре: экран входа, выбор ника, кнопка «Рейтинг», запись результата после матча, режим без входа (гость, без рейтинга).
4. Защита рейтинга от накрутки: сервер сам проверяет правдоподобность результата (максимум очков за время, число ответов), потому что игра работает на стороне клиента. Для честного рейтинга позже проверка ответов на сервере по общему seed.

**Вопросы к решению.**
- Дети 5 класса и персональные данные: хранить только внешний ID, ник и результаты, e-mail не показывать. Нужно согласие родителей и политика конфиденциальности (152-ФЗ).
- У части детей может не быть аккаунта Яндекса: оставить режим гостя и вход по телефону.
- Попросить юриста уточнить ответственность ИП по ст. 13.55 и требования 152-ФЗ при хранении данных детей (локализация данных в РФ).
- Где хостить: свой сервер с HTTPS (нужен домен).

## Бэкенд (сделано, 8 ноября 2026)

Решение владельца: вместо Яндекс ID вход через MAX; хостинг шаред (Timeweb Optimo), поэтому PHP 8.5 + MySQL 8.4 вместо Node + SQLite. БД `orgbox_school2game`, сайт https://lab.orgbox.net/school2game/.

**Вход через бота MAX.** Официального OAuth для сайтов у MAX нет, поэтому: игра просит `POST /api/auth/start`, получает 8-значный код и ссылку на бота (`MAX_BOT_LINK?start=КОД`; формат ссылки не подтверждён документацией, код можно и просто отправить боту текстом). Бот получает вебхук (`bot_started.payload` или `message_created`), привязывает MAX user_id к коду. Игра опрашивает `POST /api/auth/poll`, получает сессию в cookie (HttpOnly, SameSite=Lax). Реальное имя из MAX не сохраняется, только числовой id; ник и эмодзи-аватар выбирает ребёнок.

**API** (`/api/...`, JSON; у POST обязателен `Content-Type: application/json`): `GET health`, `POST auth/start`, `POST auth/poll`, `POST max/webhook`, `GET me`, `POST profile`, `POST logout`, `POST sync`, `GET leaderboard?period=all|week&subject=all|math|rus`.

**sync**: принимает `guestId`, `matches[]` (формат журнала матчей клиента), `stats`. Матчи проверяет `server/validate.php` (правдоподобие очков, скорости ответов, длительности, согласованность исхода и тем), добавляет идемпотентно по `id`, чужой `id` присвоить нельзя. Ответ: `accepted`, `duplicate`, `rejected[{id,reason}]` (клиент помечает все три `sent=true`), `stats` с сервера для `mergeData`. Статистика темы: побеждает вариант с большим `total`.

**Рейтинг**: сумма очков на игрока (в 2×2 очки команды делятся на 2), общий и за неделю (с понедельника по Москве), по предмету.

**Константы** игры продублированы в `server/validate.php`; при изменении правил (`POINTS_PER_PLAYER`, длина матча, бонусы) править и там.

**Запуск на сервере**: `cp .env.example .env`, вписать `DB_PASS`, `MAX_BOT_TOKEN`, `MAX_BOT_LINK`, `MAX_WEBHOOK_SECRET`; `php server/migrate.php`; `php server/max-subscribe.php` (подписка вебхука, нужен HTTPS на 443 и доверенный сертификат).

**Не подтверждено, проверить на живом боте**: формат deep link `?start=`, имя заголовка секрета `X-Max-Bot-Api-Secret` (по документации так), поведение Apache с этим заголовком (в `www/api/.htaccess` есть обход).
